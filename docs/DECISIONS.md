# Engineering decisions and open items

Firmware for the P5-IS20 PicoCar, built on the INF2004 micro T-Kernel 3.0
template. It implements the Week 6 design as amended at Tribunal 1, the
tutor review (IS20), Change Requirement 1, and the fixed wiring in
`docs/WIRING.md` (copied verbatim from
`Swan-Hein-Htet/INF2004@recovered-build-2026-10-30`, SHA-256 `ac4b989f…`;
its images live in that repository).

## 1. Decisions taken

| # | Decision | Why |
|---|---|---|
| D1 | **Kernel tick 1 ms** (`config/config.h`); T1, T2, T3, T4 released by cyclic handlers that only call `tk_wup_tsk` | Drift-free absolute release for T2's 1 kHz sampling (tribunal R1); T2 counts queued wake-ups as overruns |
| D2 | **All application tasks on core 1** (SMP build, default `make`) | The template pins the USB (pri 3) and CYW43 (pri 4) service tasks to core 0. Moving our tasks away removes R6 entirely instead of arguing priorities |
| D3 | **T1 at priority 2** | Strictly above both kernel service tasks even on an `SMP=0` build |
| D4 | **Network stays in the kernel's CYW43 task**, not in T7 | Template rule (TEAM.md §3): no application task may call cyw43/lwIP/MQTT. This supersedes the tribunal's "T7 owns the stack". T7 packs records into `mbf_telem`; `mqtt_utk.c` publishes them and pushes commands into `mbf_cmd` (all `TMO_POL`) |
| D5 | **IMU = LSM303DLHC (no gyro)**: tribunal conditional redesign applied | WIRING.md and the OKY3231-2 sheet confirm GY-511 @0x19. Pitch from gravity, with the car's own forward acceleration (from wheel speeds) removed, low-pass gated at 1 ± 0.1 g; turn rate from the wheel differential |
| D6 | **IMU fault is NOT critical** | Only hump reporting depends on it (tribunal readiness table); stopping the car for it would mirror losing WiFi (NFR19). Impact remains critical |
| D7 | **Fault mask 16 bits, 12 defined** (adds LINE_NOT_FOUND, SELF_TEST, REMOTE_STOP, TASK_OVERRUN) | Tribunal Version C chose 16 bits; the extra bits are the consolidated fault table the tutor asked for (`docs/FAULTS.md`). MQTT STOP has its own bit = the "source marker" |
| D8 | **Telemetry is 21 bytes, not 20** | The tribunal's field list sums to 164 bits once the fault mask is 16 bits (the "156 bits / 20 bytes" figure predates that change). The spare 4 bits carry the scan state |
| D9 | **No libm**: `app_math.c` (sqrt, atan2, sin, cos) | The template links no maths library; the small routines are faster on the FPU-less M0+ and verified on the host (errors < 2e-5) |
| D10 | **Own register-level drivers** for ADC, I2C0, PWM, GPIO IRQ | The kernel's ADC/I2C device-driver path is too heavy for a 1 kHz loop; drivers live in subsystem folders as the template requires |
| D11 | **One GPIO dispatcher** (IRQ 13) registered in phase 1, enabled by T4 on core 1 | One callback per core; all ISR writers and all fault writers then run on the same core, so `DI` makes `fault_set/clear` atomic |
| D12 | **Line-sensor mounting auto-detected** at calibration | Photos suggest ~27 mm sensor spacing over an 18 mm line (line BETWEEN the sensors); the earlier build assumed STRADDLE. T2 reads the centred values before the sweep and picks the right presence/loss logic |
| D13 | **Calibration sweep** S1: hold still 200 ms, then at 60 mm/s turn R35° then L35° back, then turn back by the encoder-measured overshoot (owner request 2026-11-02). Only the left sensor crosses the line: the right borrows its calibration | Gives per-channel white/black and polarity (floor is mostly white); barcode channel borrows the line calibration if it never sees black |
| D14 | **Barcode**: any Code 39 char is decoded (both directions); A/B/C pending until the junction, D immediate | Tribunal pending-command state; BARCODE.pptx contains E/F/W–Z samples, which must decode without acting |
| D15 | **Per-character ratio classification** (reference = median of the 6 narrowest of each character) | Speed-independent (NFR8) and tolerant of acceleration between characters; 20 000 jittered host trials: 0 wrong decodes |
| D16 | **Junction turn**: drive the IR-to-axle distance (70 mm) first, then turn | Puts the axle on the junction; END (all-black > 60 mm) is decided during that move and wins over the turn |
| D17 | **Handover S3→S7**: T6 flushes its queued requests, *then* publishes S7 | Flushing after the switch could discard T5's first STOP; T4 still rejects any T6-sourced request during S7 |
| D18 | **Bypass legs** use the measured obstacle edge, not a centred W/2 | `shift = edge + B/2 + 50 mm`; coarse samples are reused in the fine scan (4 new angles) to save ~0.4 s for NFR23 |
| D19 | **No-echo** = no echo edge at all for 5 pings | A clone that holds ECHO high in open space is "no return", not a fault |
| D20 | **Hardware watchdog** (500 ms) fed only by T1; off in `TEST=1` | A starved T1 resets the chip, and reset leaves the motor pins low |
| D21 | **Host simulator** (`tests/sim`) runs the unchanged application against a kernel/register/vehicle model | Every task, driver and ISR exercised together over 52 scenarios before hardware; found the defects fixed in D22-D31 |
| D22 | T2 changes line state only through `set_lstate()`: leaving L3 by any route clears LINE_LOST (and signals LINE_FOUND) | A stale LINE_LOST made T6 bounce S3/S8 forever, flooding mbf_motion and starving T7 |
| D23 | T6 decides "still lost" from the flag, not the 10 ms line word | Same bounce for up to 10 ms at every loss (sim: 100+ ERROR lines) |
| D24 | T6 clears latched START/RESET on entering S1, S2, S9, S10; publishes the state before posting FOLLOW | A START pressed mid-run restarted the car at the END marker; leaving S7, T4 could drop T6's FOLLOW |
| D25 | T2 re-arms END when the black area ends | END was latched once per power-up: a second run never stopped |
| D26 | Junction needs 12 mm of both-black (was 6) | A 9 mm barcode bar under the right line sensor read as a junction and aborted the capture |
| D27 | Mounting detected from the sweep (both sensors dark at once = STRADDLE); grey cue only if both centred channels are grey | Detection flipped with 3 mm / 3 deg placement error; a one-sided cue made the car hunt around the placement offset |
| D28 | Hump entry confirmed over 25 mm of climb | The take-off jolt read as 7 deg for 30 ms: every run started with a false hump in S6 |
| D29 | T4: skew correction applied along each wheel's direction; encoder watch reset only by counter movement; wrong-direction and no-progress-to-goal checks -> ENCODER | Backward moves span the car; a dead encoder was never detected during steering weave; a reversed motor or encoder spun the car forever in S1 |
| D30 | T5: own hits excluded from clearance; a side hit at the scan limit is not clear; both clear -> shorter way round; forward bypass legs watched by the sonar (stop < 120 mm) | Every obstacle planned REVERSE; three boxes abreast were bypassed into a box |
| D31 | Message buffers sized as the kernel accounts (4 + body rounded to 4); `ESCAPE_MM` 16; steering gains 100/150 (model-derived) | Queues held 3 and 1 instead of 4 and 2; escape 30 mm left gaps at -16 deg; 160/600 wove +-10 deg |
| D32 | **Fixed sonar by default** (`SERVO_SCAN 0`): the kit servo is an FS90R continuous-rotation servo, which sets speed, not angle. It gets no pulses; obstacles are taken as 200 mm wide and passed on the left, legs watched by the sonar. `make SERVO_SCAN=1` restores the full scan for a 180-degree servo | Owner, 2026-11-02: with any pulse other than 1.5 ms the servo span continuously |
| D33 | Floor echo of the low-mounted sonar rejected: a range that stays the same while the car drives is the floor; the trigger moves inside it; the car backs off to 180 mm before turning round an obstacle | Bench 2026-11-02: "obstacles" 160-190 mm ahead everywhere on the mat |
| D34 | Motor / encoder directions measured: left motor normal, left encoder reversed, right motor and encoder normal | Wheel test and owner observation, 2026-11-02 |
| D35 | **T4 every 10 ms** (was 20), all T4 timings derived from `S2_T4_PERIOD_MS`; steering KP 40 + leaky integral KI 200 (decay 0.3 s, reset on side change) + KD 1.0 per second; escape rule only after a contact that passed the sensor centre (`ESCAPE_PEAK` 800) | Real car 2026-11-03 slithered: error +-127, wheels 40/480 mm/s. T2 publishes every 10 ms but T4 used every other sample, and each brush got full steering. tests/sim straight, 6 seeds: wheel swing 140 -> 33 mm/s, heading rms 3.7 -> 1.0 deg |
| D36 | MQTT console (`tools/mqtt/car_console.py`): cal / go / stop / reset / status; RESET in S2/S9 recalibrates; faults, states and commands logged by name | Owner, 2026-11-03: control and full logs from the PC |
| D37 | All 43 Code 39 characters reported: the decoder always handled them; `g_barcode_last` (one byte, T2 writes) carries the real character to the `STATUS` line. Telemetry stays record v1 (none/A/B/C/D/other); bar widths by encoder distance, by time only if the car did not move | Telemetry has no spare bits and is the Change Requirement 1 interface. Checked against 43 images from bwip-js (`docs/barcodes/online_samples/`) and the Wikipedia table. Only A-D navigate; the brief gives no other meanings |
| D38 | Both reading directions verified end to end: decoder retries the reversed widths; distance and quiet-zone use unsigned encoder motion. tests/sim `bc_backward` and `bc_turned`, all 43 characters, three sizes, jerky speed. One barcode sensor, so the car must pass with the barcode on the sensor's side | Owner, 2026-11-07. The forward read fails on a reversed symbol because reversed `*` is `P`, so it cannot be misread as a valid symbol |
| D39 | Bar edges found by swing, not a fixed level: a swing of 15% back from the last peak or valley is an edge, placed where the signal crossed half way. Barcode test build: `scan` drives the car over a symbol; a hand swipe decodes on the three widest elements per character, `*` framing still required | Bench 2026-11-07: thin gaps only dip, so bars merged. Hand speed makes ratio rules useless. tests/sim normal suite 140 -> 145 of 171; 6 mm spot reads 41 of 43 with no wrong letters |

## 4. Barr-C deviations (recorded per NFR21)

- Kernel object IDs keep the template's names (`flg_sys`, `mbf_nav`,
  `tid_*`) instead of a `g_` prefix, so they match the template, TEAM.md
  and the design documents.
- Kernel types (`ID`, `ER`, `INT`, `UW`) are used at kernel API
  boundaries; application data uses `<stdint.h>` types.
- `lib/liblwip/.../mqtt_utk.c` keeps the template library's own style.
- PID integrators, filter states and set-points are task-private floats
  (Change Requirement 1 scope decision: never stored, shared or sent).
